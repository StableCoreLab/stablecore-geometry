# D1–D6 设计方案（评审稿）

状态：设计完成，代码实施待分阶段评审。本文只冻结边界、兼容策略和验收门槛，不改变当前公开 API。

## D1：模块边界与公开头

依赖方向固定为：`Types/Support → Core 结果与基础算法 → Geometry2d/Geometry3d → Brep → 应用组合`。值类型不得反向 include 算法头；Brep 可以依赖 3D 类型和 Core 结果，但 Core 不依赖 Brep。

`Geometry.h` 保持唯一 umbrella。模块头必须自洽 include；迁移期间旧路径保留转发头一个小版本，并标记弃用。实施顺序为类型、结果、接口、算法、Brep；每一步增加独立 CMake 编译目标和单头编译测试。

## D2：数值与 API 契约

新接口统一使用明确结果模型：可能失败的逆变换、投影和归一化返回 `std::optional` 或带 `issue` 的结果结构；不再用单位变换、零向量或空对象充当失败哨兵。2D/3D 容差分别保留距离、角度、参数域语义，禁止跨维度隐式换算。

旧接口保留一个兼容周期并标记 deprecated；先新增正确接口和差分测试，再迁移调用方，最后删除旧接口。成员函数与自由函数只保留一个权威入口，另一侧仅做薄转发。

## D3：空间索引产品语义

索引采用“可变容器 + lazy dirty 缓存树”模型：Add/Remove/Update 只标记 dirty，首次查询重建；显式 `Build()` 可提前重建。查询结果在同一输入和容差下保持确定顺序。

`eps` 若保留，定义为近似搜索允许的相对误差并写入 API 文档；否则从 KNN API 移除。2D/3D 先共享测试 oracle，不提前抽象为公共模板。验收使用随机数据暴力扫描对照，并覆盖更新、空索引、KNN 平局和 dirty 重建。

## D4：B-rep 数据模型与布尔

Polyhedron 是规则平面实体的输入表示，B-rep 是带拓扑所有权和曲面支持的输出/编辑表示；转换边界显式返回 `issue`。顶点、边、环、面和 shell 的所有权由 body 持有，编辑操作采用复制-重建-替换，不暴露不稳定裸引用。

Boolean 先发布能力矩阵：当前稳定子集继续明确支持范围，超出范围返回稳定 issue，不伪装成功。通用 CSG 必须分阶段实现相交、切分、分类、缝合、验证，每阶段有拓扑不变量和退化样例，不能以单一“大而全” API 承诺未实现能力。

## D5：NURBS 与数值内核

在确认权重、周期性和节点契约前，暂不把 `SCNurbs*` 宣称为完整 rational NURBS；短期文档明确其当前能力，长期可选择补齐权重或引入 `SCBSpline*` 新名。参数域、导数阶数、周期性和失败语义必须先写成契约。

数值内核共享 basis/导数实现。点-曲线、点-曲面投影作为基础内核，线-曲线和线-曲面求交复用投影/求根策略。Newton/信赖域必须定义初值、收敛阈值、最大迭代、退化输入和失败 issue，并用解析曲线、切点、窄特征和退化样例回归。

## D6：2D 多边形重建与布尔

`SearchPoly` 作为 arrangement/ring-rebuild 的唯一内部内核；`SCPathOps`、Boolean 和 CutPolygon 通过适配层调用，不复制环遍历、交点排序和 synthetic edge 处理。返回模型统一区分成功、空结果、输入无效和拓扑不确定。

epsilon 分为几何判定、拓扑合并和输出清理三层；synthetic edge 诊断保留在内部结果，只有稳定且有消费者需求的字段才提升为公开 API。迁移以现有布尔、三角化和路径测试作差分 oracle，确认输出顺序和面积不变后删除平行实现。

## 统一实施门槛

1. 每个设计包先提交 API 对照表和兼容周期说明。
2. 先增加新接口/测试，再迁移调用方，最后删除旧实现。
3. Debug、RelWithDebInfo、安装后包消费者和公开头单独编译均通过后，才标记对应设计包完成。
4. 任何能力范围变化必须同步 README、能力矩阵、使用说明和审查记录。
