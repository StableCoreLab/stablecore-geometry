# 审查问题核实与修复方案

> 基线：2026-09-01，提交 `e0872b3`。本方案核对 `审查记录.md` 所列位置后的实施拆分；它不是对算法数值正确性的重新证明。

## 核实结论

审查记录中的高危问题均可在当前基线复现。特别是：

- `GEOMETRY_BUILD_DLL` 仅以 `PRIVATE` 方式定义，`GEOMETRY_USE_DLL` 没有任何 target 定义；`Epsilon.h` 又导出了数据常量（H2）。
- `SCTransform2d::Inverse` 返回 `std::optional`，而 `SCTransform3d::Inverse` 在不可逆时返回默认构造的单位变换（H3）。
- 三个“树”在查询函数中调用 `BuildBoxTree`/`BuildKDTree`；两个 `QueryKNearest(..., double)` 实现未使用该参数（H4）。
- `BodyBoolean.cpp` 的通用路径会返回 `MakeUnsupportedResult()`；NURBS 类没有权重存储；`ShellAt`、`FaceAt` 均按值返回（H5、H6、H10）。
- `UnitTests/Gaps` 共 9 个源文件、20 个 `GTEST_SKIP()`；它们不能作为已通过的能力验证（H11）。

其余条目也与当前文件结构和实现相符。以下的“直接实施”不表示可以跳过回归测试；“需单独设计”表示在写代码前必须先完成并评审对应设计说明，不能仅靠局部重构决定接口或语义。

## 优先级与实施顺序

1. P0：先消除发布错误和假绿色（R1、R2），随后冻结公开 API 的破坏性变更入口。
2. P1：完成依赖边界与基础契约设计（D1、D2），再分批迁移；不要在旧 `Core` 目录上继续叠加新 API。
3. P2：按依赖顺序实现空间索引、B-rep、样条/通用求交和 2D 重建内核。
4. P3：收敛重复、构建安装和文档；每个包合入时删除已解决的 gap 说明并补真实断言。

## 每个修复包的统一验收

1. 为缺陷写先失败后通过的回归测试；涉及公共 ABI 的项额外编译一个安装后消费者。
2. 执行 Debug 与 Release 的构建、`ctest --output-on-failure`，并对变更的公开头执行独立 include 编译。
3. 公开 API、行为或支持范围改变时，同一变更同步更新 README、能力矩阵和迁移说明。
4. 仅在验收通过后，将 `审查记录.md` 对应条目标注“已修复”、提交号、测试名称；不要直接删除问题历史。
