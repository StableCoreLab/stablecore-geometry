# D3 空间索引性能初测

测量日期：2026-11-03。环境为当前 Windows／VS2022 x64 解决方案，分别使用 Debug、RelWithDebInfo。用例位于 `UnitTests/Capabilities/Geometry2d/TestSpatialIndexPerformance.cpp`；通过 `ctest --test-dir D:\code\StableCore\Build\GeometryVs2022 -C <配置> -R SpatialIndexPerformanceTest -V` 重现。

## 工作负载和计时边界

三个独立用例分别检查二维 KD 半径查询、二维盒范围查询、三维盒范围查询。每种使用 256、2048、8192 条有效几何、128 个确定性查询；KD 半径为 4，盒查询宽度为 8。点和盒按规则网格及 ID 顺序插入，三维盒覆盖多个 z 层；查询中心由 `(q*37)%n` 选取并偏移，盒半边长为 0.25。

构建计时包含索引构造和逐条 Add，不含几何数据生成和索引析构。索引查询计时包含结果分配及按 ID 排序；扫描计时包含逐条几何谓词及结果分配，ID 自然升序。计时之后逐查询比较完整 ID 列表，并要求总命中数非零，不仅比较数量。断言和输出均不在计时区间。

使用 steady_clock 的墙钟毫秒值。三个用例的 CTest RUN_SERIAL 均为真，标签为 performance；已检查实际生成的 CTest 属性。测试没有速度阈值，只以结果一致性判定通过。它们不强制单独运行 CTest 之外的程序保持空闲。

## 证据边界和剩余工作

这是单次、无预热、固定顺序的批量计时，不含重复样本中位数、置信区间或跨机器比较。两种方法按索引查询在先、扫描在后的顺序运行，缓存和系统负载影响未消除，表中数字不是性能承诺。

此初测只覆盖规则网格、指定规模及上述三类查询，未覆盖 KNN、近似查询、长期更新、集中重叠几何、段／曲线数值成本或任意输入。没有运行数据竞争检测工具。D3 的完整性能及并发验收仍未完成，构建耗时问题和其他数值边界继续留在修复方案；上述首轮初测已随 07aad4f 提交并暂停；用户要求恢复后的整改与验证见下节。

## 恢复后的有序构建整改

上次累计修改已提交为 `07aad4f`；用户恢复原目标后，本批新改动继续保持未提交。原表保留为当时的首轮实测，不改写历史数字。

旧实现只在插入深度超过阈值后重建整棵树；持续向同一侧插入可能反复承担整树排序成本。新实现为二维、三维盒树节点维护有效条目数量，Add 在下降前检查所选子树的预计条目数是否超过父子树的四分之三，超过时收集该父子树和新条目，构造替代子树。替代树完成前不修改原子树，失败可由 Add 撤销条目追加。删除、索引重映射和更新时的共同刷新同时维护计数。

Update 已找到 ID 时仍持有待剪枝的旧路径，故关闭插入过程中的局部重建，保留原深度检查；Update 找不到 ID 时委托 Add。此限制防止祖先替换使旧路径悬空，不将本次 Add 改善扩展为长期 Update 性能达标。

新增 `BoxTreeBalanceTest` 对两轴、三轴的有序输入和全重叠输入，各插入 8192 条，检查几何操作预算、树高、计数和完整条目索引集合，避免只用墙钟速度门槛；另检查局部重建失败不改变旧子树。计数夹具将区间作为各轴坐标相同的模型，并独立检查分割轴号处于相应维数内；真实二维、三维几何的结果由公开扫描对照覆盖。公开性能用例及长期修改 oracle 用于核对真实几何查询。五项新增用例及三项公开性能用例在 Debug 定向全部通过，完整 Debug CTest 为 1053 项登记、1037 项执行通过、16 项既有禁用。两配置最终均在下述隔离目录中重新编译并通过完整门禁。
