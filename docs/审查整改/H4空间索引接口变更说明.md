# H4 空间索引接口变更说明

## 变更范围

`SCBoxTree2d`、`SCBoxTree3d` 和 `SCKDTree2d` 改为持有并维护空间树。`Entries()` 仅返回只读 `const std::vector<...>&`；2D 类的 `Data()` 同样仅返回只读引用。原有返回可写向量引用的重载已删除，不提供兼容接口。此项变更需要调用方修改源码并重新编译。

## 调用方替换方式

原先直接修改条目向量的代码：

```cpp
tree.Entries().push_back({id, box});
tree.Entries()[index].box = newBox;
tree.Entries().erase(tree.Entries().begin() + index);
```

改为通过索引对象修改：

```cpp
tree.Add(id, box);
tree.Update(id, newBox);
tree.Remove(id);
```

对 `SCKDTree2d` 使用同名操作，几何参数为 `SCPoint2d`。原先通过 2D 类的 `Data()` 修改的调用处也按此方式替换。`Update(id, value)` 修改第一个匹配的 ID；若不存在该 ID，则新增条目。`Remove(id)` 删除所有匹配的 ID。需要按位置修改或删除时，先从只读 `Entries()` 取得对应 ID；若存在重复 ID，应先明确业务上需要修改哪一项，必要时改用唯一 ID。只读遍历、查找和复制条目仍可使用 `Entries()`；2D 类还可使用 `Data()`。

## 数据与查询契约

构造、`Add`、`Remove`、`Update` 和 `Clear` 后，树状态与条目状态同步。无效盒或无效点仍保存在 `Entries()` 中，计入 `Size()`，使 `IsValid()` 返回 `false`；无效条目不进入空间树，也不出现在空间查询结果中。将条目更新为有效几何后会进入树，更新为无效几何后会从树中移除。调用方应先使用 `IsValid()` 检查输入集合的整体有效性。

盒树的 `QueryKNearest(point, k, eps)` 按距离平方及 ID 排序。`eps <= 0` 执行精确查询；`eps > 0` 允许近似剪枝，返回的第 `k` 个距离不超过精确第 `k` 个距离的 `1 + eps` 倍。等距候选按 ID 排序。`k == 0` 返回空结果。

逐条插入及更新通常只访问相关分支，树深超过阈值时会重新平衡。`Remove(id)` 一次删除所有匹配 ID，并通过一次索引映射维护紧凑 `Entries()` 向量；盒树删除为 O(n)，KD 树删除的映射阶段为 O(n)，清理停用节点触发重建时还需承担建树成本。重合或大量重叠几何也可能增加遍历量。查询期间不重建树。外部不得并发修改同一索引对象；并发只读查询以调用方的对象生命周期管理为前提。

## 验收

仓库规则禁止 AI 编译和运行测试。人工验收应编译公开头使用方，并运行空间索引 oracle、无效条目、重复 ID、增删改、拷贝/移动和 KNN 容差用例。
