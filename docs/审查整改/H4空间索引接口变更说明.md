# H4 空间索引接口变更说明

## 变更范围

`SCBoxTree2d`、`SCBoxTree3d` 和 `SCKDTree2d` 改为持有并维护空间树。`Entries()` 仅返回只读 `const std::vector<...>&`；2D 类的 `Data()` 同样仅返回只读引用。原有返回可写向量引用的重载已删除，不提供兼容接口。此项变更需要调用方修改源码并重新编译。

## 调用方替换方式

原先直接修改条目向量的代码：

```cpp
tree.Entries().push_back({id, box});
tree.Entries()[index].box = newBox;
tree.Entries().erase(tree.Entries().begin() + index);
```

改为通过索引对象修改：

```cpp
tree.Add(id, box);
tree.Update(id, newBox);
tree.Remove(id);
```

对 `SCKDTree2d` 使用同名操作，几何参数为 `SCPoint2d`。原先通过 2D 类的 `Data()` 修改的调用处也按此方式替换。`Update(id, value)` 修改第一个匹配的 ID；若不存在该 ID，则新增条目。`Remove(id)` 删除所有匹配的 ID。需要按位置修改或删除时，先从只读 `Entries()` 取得对应 ID；若存在重复 ID，应先明确业务上需要修改哪一项，必要时改用唯一 ID。只读遍历、查找和复制条目仍可使用 `Entries()`；2D 类还可使用 `Data()`。

## 数据与查询契约

构造、`Add`、`Remove`、`Update` 和 `Clear` 后，树状态与条目状态同步。无效盒或无效点仍保存在 `Entries()` 中，计入 `Size()`，使 `IsValid()` 返回 `false`；无效条目不进入空间树，也不出现在空间查询结果中。将条目更新为有效几何后会进入树，更新为无效几何后会从树中移除。调用方应先使用 `IsValid()` 检查输入集合的整体有效性。

盒树的 `QueryKNearest(point, k, eps)` 按欧氏距离及 ID 排序，命中载荷保留平方距离字段。`eps <= 0` 执行精确查询；`eps > 0` 允许近似剪枝，返回的第 `k` 个距离不超过精确第 `k` 个距离的 `1 + eps` 倍。等距候选按 ID 排序。`k == 0` 返回空结果。欧氏距离可表示但平方距离溢出或下溢时，排序及剪枝仍按欧氏距离执行。

有限点与盒坐标的欧氏距离也溢出时，盒树用四分之一尺度的坐标差比较候选、节点下界与近似剪枝；命中载荷中的平方距离仍可能为无穷。

`SCKDTree2d::Nearest` 与 `QueryWithinDistance` 的候选比较和剪枝按欧氏距离执行，即使距离平方溢出或下溢仍可区分可表示的距离；负值及 NaN 查询半径返回空。`Nearest` 命中载荷仍使用 `double distanceSquared`，当平方距离不可表示时可能为无穷，此时 `SCKDTreeHit2d::IsValid()` 返回假。

`Nearest` 在有限坐标相减后欧氏距离也溢出时，使用四分之一尺度的坐标差比较候选与分割面下界；返回载荷的平方距离仍可能为无穷。

三种索引的点查询入口均要求查询点 `IsValid()`；NaN 或无穷坐标返回空结果，KD 树 `Nearest` 返回 `std::nullopt`。

逐条插入及更新通常只访问相关分支，树深超过阈值时会重新平衡。`Remove(id)` 一次删除所有匹配 ID，并通过一次索引映射维护紧凑 `Entries()` 向量；盒树删除为 O(n)，KD 树删除的映射阶段为 O(n)，清理停用节点触发重建时还需承担建树成本。重合或大量重叠几何也可能增加遍历量。查询期间不重建树。外部不得并发修改同一索引对象；并发只读查询以调用方保证对象生存期和无并发写入为前提。2D/3D 盒树及二维 KD 树的四线程重复只读查询已有回归覆盖；这项回归不替代数据竞争检测工具。

## 复杂度与并发边界

以下按当前实现推导，不是性能基准。令 `n = Size()`（含无效条目）、`m` 为有效条目数、`h` 为实际树高、`r` 为返回条目数、`k' = min(k, m)`。表中忽略固定维数的几何计算成本；对空集合使用常数时间边界。

| 操作 | 2D/3D 盒树 | 二维 KD 树 |
| --- | --- | --- |
| 构造、重建、复制 | `O(n + m log²(m + 1))`；每层重新排序并二分 | 平均 `O(n + m log(m + 1))`；每层使用 `std::nth_element`，不承诺其最坏线性选择成本 |
| `Add`，未触发重建 | 分支维护 `O(h + 1)`；条目向量追加均摊 `O(1)`，单次扩容 `O(n)` | 同左 |
| `Update`，ID 已存在 | 先线性找 ID，再找旧叶及插入；最坏 `O(n + h)` | 先线性找 ID，再停用旧节点及插入；最坏 `O(n + h + 1)`，含停用节点遍历 |
| `Remove` | 映射、条目压缩及树节点维护合计 `O(n)` | 映射、条目压缩及节点遍历为 `O(n + 1)`；触发清理时另加重建成本 |
| `Find`、按 ID 的 `Contains`、`IsValid` | 最坏 `O(n)` | 同左 |
| 范围、点、半径、最近邻查询 | 适用的范围和点查询最坏 `O(n)`；递归栈及结果占 `O(h + r)` | 最坏 `O(n + 1)`；递归栈及结果占 `O(h + r + 1)` |
| `QueryKNearest` | 最坏 `O(n log(k' + 2) + k' log(k' + 1))`；递归栈及候选占 `O(h + k')` | 无此接口 |

`Update` 找不到 ID 时等同 `Add`，找到时及 `Add` 本身均可能触发重建，届时须加上建树成本。深度阈值为 `2 * bit_width(n) + 8`，检查的是本次插入路径；不能据此宣称任意增删改序列均有对数时间或已证明的均摊更新上界。盒树删除会压缩空节点和单子节点，但不立即全局重平衡。KD 树保留停用节点，在节点数超过 `2 * n + 32` 时重建；正常完成操作后的节点数为 `O(n + 1)`。重叠、重复坐标及不利查询可使访问量达到线性，树高较小也不保证查询只访问对数个节点。

树节点及有效条目索引占 `O(n + 1)`，重建和删除的临时存储占 `O(n + 1)`。条目向量的实际存储另取决于其 `capacity()`：删除与 `Clear()` 不承诺释放容量，不能把常驻内存严格绑定到删除后的 `Size()`。构造、复制与重建的峰值还包含原树和新树同时存在的空间。

查询只读取条目和节点，候选、递归状态和结果均为每次调用的局部数据，不使用延迟重建或共享可写缓存。因此可以在对象生存期稳定、所有线程均不修改对象时并发调用只读查询。`Add`、`Update`、`Remove`、`Clear`、赋值及析构与任何访问并发时，调用方必须同步。`Entries()`、`Data()` 返回的向量引用和 `Find()` 返回的指针不是快照；跨修改保存时应遵循向量元素失效规则，析构后均不可再用。查询返回的向量及命中值为独立副本。

上述边界来自对 `Source/Detail/BoxTreeCore.h`、`Source/Core/SCBoxTree2d.cpp`、`SCBoxTree3d.cpp` 和 `SCKDTree2d.cpp` 的静态审查。四线程回归仅提供并发只读的功能证据；未执行数据竞争检测或性能基准，D3 的剩余验收不得据此整体标记完成。
