# L13 网格查询与修复职责

核对日期：2026-11-03。以下按当前实现划分职责，不改变接口或扩展网格修复能力。

## 主入口与依赖方向

| 层与文件 | 职责 | 输出与写入边界 |
|---|---|---|
| `Include/Brep/MeshOps.h`、`Source/Brep/MeshOps.cpp` | 三角形／顶点法线、邻接、边界边与环、非流形边、连通分量、定向一致性及 shell 诊断 | 接受 `const TriangleMesh&`，返回独立查询结果，不修改输入 |
| `Include/Core/MeshRepair.h`、`Source/Core/MeshRepair.cpp` | 根据查询结果执行定向与平面边界封口策略 | 返回 `TriangleMeshRepair3d`；只修改局部网格副本，失败时返回具名问题 |
| `Include/Brep/MeshRepair.h` | 旧包含路径兼容 | 转发到 Core 主头，不定义第二套修复算法 |

依赖方向是 `Core/MeshRepair → Brep/MeshOps`。底层查询不反向包含 Core，也不调用三角化；封口依赖 Core 的 `Triangulate`，因此仍放在 Core。不得为统一文件名将修复实现移回 Brep，或将只读诊断改成隐式修复。

## 现有调用证据

- `OrientTriangleMeshConsistently` 先用 `IsManifoldTriangleMesh` 和 `ComputeTriangleAdjacency` 判断可处理输入，再计算各三角面的翻转奇偶；只在复制出的 `repaired.Triangles()` 中交换索引。矛盾奇偶返回 `NonOrientable`。
- `CloseSinglePlanarBoundaryLoop` 用 `ExtractBoundaryLoops` 检查单个闭环，随后委托 `ClosePlanarBoundaryLoops`，没有另一套独立封口实现。
- `ClosePlanarBoundaryLoops` 使用相同的边界环查询，在局部平面投影中调用 `Triangulate`，向副本追加三角面，最后委托 `OrientTriangleMeshConsistently`。非平面边界、开放轮廓或不可支持拓扑仍返回失败。
- `MeshOps.cpp` 的边记录收集用于多个只读查询；修复层消费公开查询结果，不重新实现完整边界环提取或流形诊断。

## 剩余边界与复审

公开职责及调用方向已经分开；历史上“职责仍有重叠”的泛称不能代替具体缺口。两个实现文件的三角形有向边枚举现共用内部 `Source/Detail/TriangleEdges3d.h`，仅依赖标准库，按原顶点次序返回 `(0,1)、(1,2)、(2,0)`；边下标、边方向及修复时共享边核验顺序保持。修复层仍按邻接三角形核查共享边方向，不将策略判断强行并入查询层。此次仅合并明确相同的枚举逻辑，不据此宣称内部实现已完全去重。一般非平面封口、非流形修复和更广的修复策略仍属于原 D4／D6 能力边界。

第一次复审按公开声明分类，第二次逐项核对副本写入位置、查询委托及 Core 依赖。两次均未发现与上表相矛盾的公开职责或隐式输入修改。现有网格能力与修复测试提供行为证据，ModuleDependencies 提供文字 include 的层级证据；这些检查不代替一般修复能力验收。
