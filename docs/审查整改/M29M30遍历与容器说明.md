# M29–M30 遍历与容器边界

## M29 B-rep 环遍历

`Source/Brep/LoopGeometry.h` 是 B-rep 环到顶点序列的内部入口。`TryGetCoedgeVertexIndices` 统一处理 coedge 的正反方向与边、顶点索引校验；`AppendRawLoopVertices` 从转换阶段尚未组装成 `SCBrepBody` 的独立数组提取原始顶点；`AppendLoopVertices` 从已组装 body 提取并按调用方容差清理连续重复点。两种顶点输出保留各自的清理契约，但共用索引解析。`BrepConversion.cpp` 与 `Healing.cpp` 现调用该入口。

`BrepLoopGeometryTest.ResolvesForwardAndReversedCoedgesFromIndependentArrays` 覆盖反向 coedge、原始环顶点顺序以及边、顶点越界；现有三维转换、修复和 Boolean 测试覆盖公开行为。

后续复审将 `BodyBoolean` 的单 shell 流形校验和 `GeometryEvidence3d` 的闭合拓扑核验改为复用 `TryGetCoedgeVertexIndices`。几何证据中的半开射线环还使用 `AppendRawLoopVertices` 提取原始顶点；无效索引时返回未知判定，避免直接按索引访问。环闭合、边使用次数和方向平衡仍由各自调用点校验。

`GeometryEvidence3d` 的 B-rep 射线环适配器也已改用 `TryGetCoedgeVertexIndices`，保留 coedge 方向及顶点身份；解析失败时返回未知判定，避免直接索引访问。外层仍先验证 body，射线环只负责提取分类器所需的数据视图。

`Source/Core/Detail/BrepFaceRegion.h` 的平面 trim 构造现也复用 `TryGetCoedgeVertexIndices` 解析 coedge 方向并校验边、顶点索引；边曲线端点对应、环连续性和 UV 投影仍由该构造入口校验。`Measure`、`Projection3d`、`Intersection3d` 和 `GeometryEvidence3d` 经此共用同一索引解析逻辑。

`Healing` 的保守 shell 闭合推断现同时统计每条边的使用次数与 coedge 方向平衡。原先两张同向重复面各用同一边一次也会被标为闭合；公开回归先复现，再验证修复后保持开放，正反配对面仍可判为闭合。该入口仍只根据已有 shell 的边使用关系推断，不替代完整的 B-rep 流形校验。

`Validate(SCBrepBody)` 的边邻接统计现按 coedge 的 `EdgeIndex()` 分别计数。原按无向端点对合并时，一条已使用边会掩盖同端点的未使用边；公开回归先复现误报有效，再验证未使用边按自身索引报告 `InvalidFaceAdjacency`。两条同端点但不同索引的边各被使用一次仍可通过；遍历改用只读引用访问器以避免复制 body 的边、面与壳。

## M30 容器与命中类型

`Source/Detail/GeometryContainerOps.h` 已集中 `ContainerCount`、`ContainerIsEmpty`、`ContainerIsValid` 和 `FindEntryById`，分别提供计数、空值、元素有效性及按 ID 查找的共同逻辑，两个 Multi 容器、三个二维索引和两个三维索引复用适用的函数。`SCBoxTree3d::Find` 与二维盒树一样复用线性 ID 查找；`SCSegmentSearch3d::Find` 保留其更新时维护的 ID 映射。公开计数主入口为 `Size()`，旧 `Count()` 仅在原有容器保留兼容；具名集合访问器是主入口，旧 `Data()` 标记为弃用。

空间索引按实际查询签名保留各自载荷：

| 索引与入口 | 返回内容 |
| --- | --- |
| 二维、三维盒树的 `Query`、`QueryContaining` | `std::vector<std::size_t>`，仅含 ID |
| 二维、三维盒树的 `QueryKNearest` | `SCBoxTreeKnnHit2d/3d` 数组，含 ID、盒及平方距离 |
| 二维 KD 树的 `Query`、`QueryWithinDistance` | ID 数组 |
| 二维 KD 树的 `Nearest` | `std::optional<SCKDTreeHit2d>`，含 ID、点及平方距离 |
| 二维、三维段搜索的 `QueryWithinDistance`、`QueryKNearest` | `SCSegmentSearchHit2d/3d` 数组，含 ID、投影点、平方距离、曲线参数及原参数域内标志 |
| 二维、三维段搜索的 `Nearest` | 对应段搜索命中的 `std::optional` |

`SCBoxTreeHit2d` 仍是公开的 ID 与盒记录，当前盒树查询签名没有使用它，保留类型以维持源码兼容。增删改还须维护各索引不同的树结构和 ID 规则，因此不通过公共基类合并这些公开结果布局或更新路径。统一的 KNN、更新与距离语义由空间索引接口说明和 oracle 测试验证。

`SCSegmentSearchHit2d/3d::IsValid()` 要求投影点有效、参数有限，平方距离有限且非负，与投影结果及 KD 命中的数值规则保持一致。参数不强制限制到 `[0, 1]`，因为三维曲线可以具有其他参数域；是否在原参数域内由具体查询生成 `isOnSegment` 标志。`IsValid()` 不检查 ID 是否属于某个索引，也不替代查询是否返回值的判断；平方距离不可表示的载荷不能通过此有限值检查。没有命中时由空数组或空 `std::optional` 表示，不为不同索引强加统一的空命中布局。

拓扑容器也使用 `Size()`：`PolygonTopology2d` 仍统计保存的多边形数量，`SCSectionTopology3d` 仍统计拓扑节点数量。两者原有 `Count()` 保留并转发到 `Size()`，标记 `deprecated`；旧二进制入口及对象布局保持兼容。内部截面转换与调试输出改用主入口，主要能力测试及布尔测试助手同步迁移，四处明确的旧调用继续覆盖兼容行为；不将此收敛扩展为统一的公开容器基类。

`SCSegmentSearch2d` 的半径筛选、最近邻和 KNN 排序使用查询点到投影点的欧氏距离，避免可表示的小距离在平方下溢后误判为零或错误并列。返回载荷继续保留原 `distanceSquared`，该字段可能下溢为零；投影及命中原有的有限平方距离要求仍保留，因此本项不扩大平方溢出时的支持范围。`Nearest` 的等距候选保留条目遍历顺序，KNN 等距按 ID 排序；负值或 NaN 半径返回空，正无穷上限保持允许。三个公开回归先复现半径零误命中、最近邻错误和 KNN 排序错误，再验证修复；对象布局与公开签名不变。

二维／三维段搜索的扫描、候选扩张、内存及底层几何并发条件另见 [D3段搜索复杂度与并发边界](D3段搜索复杂度与并发边界.md)。盒树并发只读回归不能直接证明用户曲线子类的线程安全。
