# M29–M30 遍历与容器边界

## M29 B-rep 环遍历

`Source/Brep/LoopGeometry.h` 是 B-rep 环到顶点序列的内部入口。`TryGetCoedgeVertexIndices` 统一处理 coedge 的正反方向与边、顶点索引校验；`AppendRawLoopVertices` 从转换阶段尚未组装成 `SCBrepBody` 的独立数组提取原始顶点；`AppendLoopVertices` 从已组装 body 提取并按调用方容差清理连续重复点。两种顶点输出保留各自的清理契约，但共用索引解析。`BrepConversion.cpp` 与 `Healing.cpp` 现调用该入口。

`BrepLoopGeometry3dTest.ResolvesForwardAndReversedCoedgesFromIndependentArrays` 覆盖反向 coedge、原始环顶点顺序以及边、顶点越界；现有三维转换、修复和 Boolean 测试覆盖公开行为。

后续复审将 `BodyBoolean` 的单 shell 流形校验和 `GeometryEvidence3d` 的闭合拓扑核验改为复用 `TryGetCoedgeVertexIndices`。几何证据中的半开射线环还使用 `AppendRawLoopVertices` 提取原始顶点；无效索引时返回未知判定，避免直接按索引访问。环闭合、边使用次数和方向平衡仍由各自调用点校验。

`GeometryEvidence3d` 的 B-rep 射线环适配器也已改用 `TryGetCoedgeVertexIndices`，保留 coedge 方向及顶点身份；解析失败时返回未知判定，避免直接索引访问。外层仍先验证 body，射线环只负责提取分类器所需的数据视图。

`Source/Core/Detail/BrepFaceRegion.h` 的平面 trim 构造现也复用 `TryGetCoedgeVertexIndices` 解析 coedge 方向并校验边、顶点索引；边曲线端点对应、环连续性和 UV 投影仍由该构造入口校验。`Measure`、`Projection3d`、`Intersection3d` 和 `GeometryEvidence3d` 经此共用同一索引解析逻辑。

`Healing` 的保守 shell 闭合推断现同时统计每条边的使用次数与 coedge 方向平衡。原先两张同向重复面各用同一边一次也会被标为闭合；公开回归先复现，再验证修复后保持开放，正反配对面仍可判为闭合。该入口仍只根据已有 shell 的边使用关系推断，不替代完整的 B-rep 流形校验。

`Validate(SCBrepBody)` 的边邻接统计现按 coedge 的 `EdgeIndex()` 分别计数。原按无向端点对合并时，一条已使用边会掩盖同端点的未使用边；公开回归先复现误报有效，再验证未使用边按自身索引报告 `InvalidFaceAdjacency`。两条同端点但不同索引的边各被使用一次仍可通过；遍历改用只读引用访问器以避免复制 body 的边、面与壳。

## M30 容器与命中类型

`Source/Detail/GeometryContainerOps.h` 已集中 `ContainerCount`、`ContainerIsEmpty`、`ContainerIsValid`、`ContainerTotalCount`、ID 迭代器／指针查找及带位置映射的条目删除，分别提供计数、空值、元素有效性及按 ID 查找的共同逻辑，两个 Multi 容器、三个二维索引和两个三维索引复用适用的函数。`SCBoxTree3d::Find` 与二维盒树一样复用线性 ID 查找；`SCSegmentSearch3d::Find` 保留其更新时维护的 ID 映射。公开计数主入口为 `Size()`，旧 `Count()` 仅在原有容器保留兼容；具名集合访问器是主入口，旧 `Data()` 标记为弃用。

空间索引按实际查询签名保留各自载荷：

| 索引与入口 | 返回内容 |
| --- | --- |
| 二维、三维盒树的 `Query`、`QueryContaining` | `std::vector<std::size_t>`，仅含 ID |
| 二维、三维盒树的 `QueryKNearest` | `SCBoxTreeKnnHit2d/3d` 数组，含 ID、盒及平方距离 |
| 二维 KD 树的 `Query`、`QueryWithinDistance` | ID 数组 |
| 二维 KD 树的 `Nearest` | `std::optional<SCKDTreeHit2d>`，含 ID、点及平方距离 |
| 二维、三维段搜索的 `QueryWithinDistance`、`QueryKNearest` | `SCSegmentSearchHit2d/3d` 数组，含 ID、投影点、平方距离、曲线参数及原参数域内标志 |
| 二维、三维段搜索的 `Nearest` | 对应段搜索命中的 `std::optional` |

`SCBoxTreeHit2d` 仍是公开的 ID 与盒记录，当前盒树查询签名没有使用它，保留类型以维持源码兼容。增删改还须维护各索引不同的树结构和 ID 规则，因此不通过公共基类合并这些公开结果布局或更新路径。统一的 KNN、更新与距离语义由空间索引接口说明和 oracle 测试验证。

`SCSegmentSearchHit2d/3d::IsValid()` 要求投影点有效、参数有限，平方距离有限且非负，与投影结果及 KD 命中的数值规则保持一致。参数不强制限制到 `[0, 1]`，因为三维曲线可以具有其他参数域；是否在原参数域内由具体查询生成 `isOnSegment` 标志。`IsValid()` 不检查 ID 是否属于某个索引，也不替代查询是否返回值的判断；平方距离不可表示的载荷不能通过此有限值检查。没有命中时由空数组或空 `std::optional` 表示，不为不同索引强加统一的空命中布局。

拓扑容器也使用 `Size()`：`PolygonTopology2d` 仍统计保存的多边形数量，`SCSectionTopology3d` 仍统计拓扑节点数量。两者原有 `Count()` 保留并转发到 `Size()`，标记 `deprecated`；旧二进制入口及对象布局保持兼容。内部截面转换与调试输出改用主入口，主要能力测试及布尔测试助手同步迁移，四处明确的旧调用继续覆盖兼容行为；不将此收敛扩展为统一的公开容器基类。

`SCSegmentSearch2d` 的半径筛选、最近邻和 KNN 排序使用查询点到投影点的欧氏距离，避免可表示的小距离在平方下溢后误判为零或错误并列。返回载荷继续保留原 `distanceSquared`，该字段可能下溢为零；投影及命中原有的有限平方距离要求仍保留，因此本项不扩大平方溢出时的支持范围。`Nearest` 的等距候选保留条目遍历顺序，KNN 等距按 ID 排序；负值或 NaN 半径返回空，正无穷上限保持允许。三个公开回归先复现半径零误命中、最近邻错误和 KNN 排序错误，再验证修复；对象布局与公开签名不变。

二维／三维段搜索的扫描、候选扩张、内存及底层几何并发条件另见 [D3段搜索复杂度与并发边界](D3段搜索复杂度与并发边界.md)。盒树并发只读回归不能直接证明用户曲线子类的线程安全。

## 原始重复点逐项复核（2026-11-04）

本节按初始审查 9767303 的 M29／M30 核对当前实现归属，不用文件名相似或已存在共同助手代替调用点证据。

| 原 M29 调用方 | 当前共同入口与保留职责 |
|---|---|
| BrepConversion | Source/Brep/BrepConversion.cpp 调用 AppendLoopVertices 取得 body 面外环／孔；未组装数组的解析复用 TryGetCoedgeVertexIndices |
| BodyBoolean | Source/Core/BodyBoolean.cpp 的面区域、环匹配及比较调用 AppendLoopVertices；单 shell 闭合校验复用 TryGetCoedgeVertexIndices，边使用和流形规则独立保留 |
| MeshConversion | Source/Core/MeshConversion.cpp 的外环与孔均调用 AppendLoopVertices，不再各自复制 coedge 方向解析 |

共同 UV 函数先通过 TryAffinePlaneUv 解算并核验重建点有限性。VerifyOriginalVertex 还检查残差不超过线性 epsilon；ApproximateRepair 接受有限 UV，不要求原顶点位于拟合平面。两种用途有意不同，不能为去重而取消修复策略。BrepLoopGeometry3dTest 的独立数组测试证明正反 coedge 及越界行为；公开转换／修复／布尔回归提供调用方证据，但不据此宣称所有极端平面投影已完备。

| 原 M30 操作族 | 共同实现与不能机械合并的部分 |
|---|---|
| 计数、空值、元素有效性 | 两个 Multi 容器及适用的二／三维索引使用 GeometryContainerOps.h；公开主计数为 Size，原 Count 仅弃用转发 |
| 按 ID 查找 | 二维盒树、KD 树、二维段搜索及三维盒树使用 FindEntryById；三维段搜索使用其维护的 ID 映射 |
| 增删改 | Multi 保存值序列；盒树与 KD 树须同步节点和条目索引；二维段搜索还保留可写 Entries，三维段搜索维护缓存及映射。因此仅共用适用的基础操作，不将不同状态维护抽成同一个无语义基类 |
| 命中载荷 | ID 数组、盒近邻、点近邻和曲线投影记录按实际查询返回信息区分；旧未使用的公开记录按兼容规则保留，不以统一布局丢弃曲线参数等信息 |

## M30 共同循环与有状态索引步骤的进一步收敛

2026-11-05：本阶段继续按原始 M30 的操作族核对，不只将已存在的 Size／IsEmpty 包装当作所有重复循环均已消除的证据。

| 共同入口 | 当前使用方 | 保留的语义 |
|---|---|---|
| ContainerIsValid(values, predicate) | SCMultiPolygon2d／SCMultiPolyline2d 的显式 IsValid(eps) | 调用点先拒绝非正、NaN、无穷 epsilon，再按顺序短路校验元素；无参数重载仍按元素默认有效性校验 |
| ContainerTotalCount(values, countOf) | 两个 Multi 的 PointCount／SegmentCount，以及 MultiPolygon 的 HoleCount，共五处 | 依次累计所选具名指标；不把 Size 换成顶点数，不过滤无效元素，不新增溢出、修复或容差策略 |
| FindEntryIteratorById(values, id) | 二维／三维盒树及二维 KD 树的 Update；原 FindEntryById 也委托该入口 | 保留 const／可写迭代器类型及首个匹配 ID；返回指针的公开 Find 仍遵从原生命周期边界 |
| EraseEntriesByIdWithMapping(values, id) | 二维／三维盒树及二维 KD 树的 Remove | 删除所有匹配 ID、保持剩余条目顺序，返回删除前到删除后位置映射；无匹配时返回空 optional 且不修改序列 |

两个显式校验循环、五个具名计数循环、三个更新 ID 定位和三个删除映射步骤现只保留共同算法。默认校验展开后与原 all_of 表达式逐字一致；无效 epsilon 在空 Multi 上仍被拒绝，默认空集合有效性及零计数继续保持。

删除映射的被删位置仍用原序列长度作为哨兵，其余位置依次编号。映射在改动条目前分配，与旧路径的异常顺序相同；返回时移动 vector，不在条目删除后新增映射分配。盒树随后执行自己的 RemapIndices；KD 树执行其节点重映射、空树处理及墓碑数量阈值清理。Update 仅替换查找步骤，节点停用、重插、平衡、包围盒维护与异常回滚保持原语句。

Add／Clear 中适用的值序列操作已直接使用 std::vector；索引还必须维护根节点、自动 ID 或墓碑计数，不新增无意义的一层公共基类。二维段搜索 Remove 不需要位置映射，因此继续直接擦除匹配条目，不因共享而引入额外分配；三维段搜索继续保留维护好的 ID 映射。不同命中载荷及默认／显式 Bounds 的无效元素策略未合并。
