# M29–M30 遍历与容器边界

## M29 B-rep 环遍历

`Source/Brep/LoopGeometry.h` 是 B-rep 环到顶点序列的内部入口。`TryGetCoedgeVertexIndices` 统一处理 coedge 的正反方向与边、顶点索引校验；`AppendRawLoopVertices` 从转换阶段尚未组装成 `SCBrepBody` 的独立数组提取原始顶点；`AppendLoopVertices` 从已组装 body 提取并按调用方容差清理连续重复点。两种顶点输出保留各自的清理契约，但共用索引解析。`BrepConversion.cpp` 与 `Healing.cpp` 现调用该入口。

`BrepLoopGeometryTest.ResolvesForwardAndReversedCoedgesFromIndependentArrays` 覆盖反向 coedge、原始环顶点顺序以及边、顶点越界；现有三维转换、修复和 Boolean 测试覆盖公开行为。

后续复审将 `BodyBoolean` 的单 shell 流形校验和 `GeometryEvidence3d` 的闭合拓扑核验改为复用 `TryGetCoedgeVertexIndices`。几何证据中的半开射线环还使用 `AppendRawLoopVertices` 提取原始顶点；无效索引时返回未知判定，避免直接按索引访问。环闭合、边使用次数和方向平衡仍由各自调用点校验。

`Source/Core/Detail/BrepFaceRegion.h` 的平面 trim 构造现也复用 `TryGetCoedgeVertexIndices` 解析 coedge 方向并校验边、顶点索引；边曲线端点对应、环连续性和 UV 投影仍由该构造入口校验。`Measure`、`Projection3d`、`Intersection3d` 和 `GeometryEvidence3d` 经此共用同一索引解析逻辑。

## M30 容器与命中类型

`Source/Detail/GeometryContainerOps.h` 已集中 `Count`、`IsEmpty`、元素有效性及按 ID 查找的共同逻辑，两个 Multi 容器、三个二维索引和两个三维索引复用适用的函数。`SCBoxTree3d::Find` 与二维盒树一样复用线性 ID 查找；`SCSegmentSearch3d::Find` 保留其更新时维护的 ID 映射。公开计数主入口为 `Size()`，旧 `Count()` 仅在原有容器保留兼容；具名集合访问器是主入口，旧 `Data()` 标记为弃用。

空间索引的命中类型保留各自载荷：`SCBoxTreeHit2d` 返回盒，`SCKDTreeHit2d` 返回点和距离，`SCSegmentSearchHit2d` 返回投影点、参数及在线段内标志。增删改还须维护各索引不同的树结构和 ID 规则，因此不通过公共基类合并这些公开结果布局或更新路径。统一的 KNN、更新与距离语义由空间索引接口说明和 oracle 测试验证。
