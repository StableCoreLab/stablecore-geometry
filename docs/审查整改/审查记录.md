## 一、总体结论

库的整体工程健康度是 **中上**：构建与测试基线稳定、Debug/RelWithDebInfo 均为 340 项通过且 19 项明确禁用；Types 值类型层干净、2D/3D 平行做得用心；Brep 顶层 API 风格（结果结构 + issue 枚举 + 可选返回）统一；无 "not implemented" 抛异常残留。

但在结构层面存在 **5 个必须优先处理的系统性问题**：

1. **分层失效（最高优先）**：`Core/` 目录同时充当"底层结果类型"和"顶层算法门面"，与 Geometry2d / Geometry3d / Brep 三层互相 include 成环；`Source/Geometry3d` 与 `Source/Core` 的实现层反向寄生在 Brep 之上。目录命名暗示的分层与实际依赖方向几乎相反。
2. **导出/DLL 契约断裂（发布前必修）**：全库从未定义 `GEOMETRY_USE_DLL`，消费者侧 `dllimport` 整条链失效；`Support/Epsilon.h` 导出的 33 个数据常量（`kPi`、`kArcBoundsCriticalAngles` 及各 epsilon）在 MSVC 下会被消费者读成导入表地址位，值错误。
3. **接口契约四分五裂**：矩阵/变换求逆的失败语义在 2D/3D 间有三种并存（`std::optional` / 单位变换哨兵 / 零矩阵），其中 `SCTransform3d::Inverse` 用"单位变换"伪装"求逆失败"；2D/3D 类型家族泛化策略分叉（模板 vs 非模板、class vs struct）是一系列不一致的根源。
4. **名不副实与空壳 API**：`SCBoxTree2d/3d` 与 `SCKDTree2d` 名不副实（每次查询全量重建、`QueryKNearest` 的 eps 形参被忽略）；`BodyBoolean` 只支持"相同/相离/单轴对齐盒"三种平凡情形；`SCNurbsCurve3d/Surface` 名不副实（无权重，实为 B-spline，导数为有限差分）；`Heal(PolyhedronBody)` 是无操作空实现。
5. **测试体系结构性失衡**：Gaps 目录 20 个测试全部是 `GTEST_SKIP()` 占位（CTest 假绿、文档被塞进字符串）；全库零 fixture / 零参数化，`TestCore.cpp` 单个 TEST 达 1391 行，立方体构造器重复 4~5 份。

次要但值得注意的：大量算法重复实现（三角化 3 份、多边形重建 2 份、环→顶点遍历 4 份、求交/投影采样器 3 份）；`GeometryTypes.h` 巨型结果目录、`Sdk` 死别名等收敛残骸；文档（README、final-naming-plan、coding-style、CI 声明）与代码现状多处脱节。

## 二、高危结构问题（发布前必须处理）

### H1. Core 层与 Geometry2d/3d/Brep 三层互相 include 成环，分层名存实亡

- **位置**：`Include/Core/Intersection.h:3-15`、`Measure.h:5-14`、`Projection.h:3-17`、`Relation.h:3-17`、`Section.h:4-10`、`Validation.h:3-9`、`Geometry2d/SCSegmentSearch2d.h:10`、`Geometry3d/ISCCurve3d.h:5`、`Brep/SCBrepBody.h` 等
- **描述**：`Core/` 目录混装了两种东西——(a) 底层叶子类型（`GeometryTypes.h`/`GeometryTypesPrimitives.h`/`Results.h`）与 (b) 顶层算法模块（Intersection/Measure/Projection/Relation/Section/Validation），后者 include Geometry2d/3d 与 Brep。同时 `Geometry3d/ISCCurve3d.h` include `Core/GeometryTypesPrimitives.h`，`Geometry2d/SCSegmentSearch2d.h` include `Core/Intersection.h`。于是双向依赖环：Core↔Geometry2d、Core↔Geometry3d、Core↔Brep 全成环，与 `docs/library-design.md` §5/§6 规定的分层（Types/Support 底层、Brep 高阶）直接冲突。后果：头文件必须"任意顺序可 include"才编译得过，任何单点改动都可能触发全库重编，PCH 也被迫拖入整棵依赖树。
- **建议**：把 `SCGeometryTolerance3d`/`SCCurveEval3d`/`SCSurfaceEval3d` 及 `GeometryTypes.h` 中的结果类型下沉到 `Types/`（或新建 `Include/Foundation/`）；把 Brep/Polyhedron 相关的 Intersect/Projection/Relation/Section 自由函数下沉到 `Source/Brep/`；消除 `SCSegmentSearch2d.h` 对 `Core/Intersection.h` 的 include。构建系统层面拆出 2D/3D/Brep 依赖边界（或至少分 target）。

### H2. 消费者侧 `GEOMETRY_USE_DLL` 从未定义，导出数据在 MSVC 下读错

- **位置**：`CMakeLists.txt:179`（`GEOMETRY_BUILD_DLL` 为 PRIVATE）、`cmake/SCGeometryConfig.cmake.in`、`Include/Export/GeometryExport.h:3-13`、`Include/Support/Epsilon.h:10-117`（33 个 `extern GEOMETRY_API const`）
- **描述**：`GEOMETRY_USE_DLL` 只出现在 `GeometryExport.h` 的 `#elif` 分支里，全仓无任何 target 定义它。库自身 `GEOMETRY_BUILD_DLL`（PRIVATE）→ `dllexport` 正常；但所有消费者（in-tree 测试与 `find_package` 用户）编译时 `GEOMETRY_API` 为空，对**函数**只是性能损失，对**数据**是实打实错误——MSVC 下未标注 `dllimport` 的导出数据会被当作导入表 thunk 地址读出。`Epsilon.h` 里 33 个导出常量（`kPi`、`kTwoPi`、`kArcBoundsCriticalAngles`、各 epsilon）正是数据导入，消费者直接读取即得错值。
- **建议**：`target_compile_definitions(${SCGEOMETRY_TARGET} INTERFACE GEOMETRY_USE_DLL)`，随 `install(EXPORT)` 写入 `INTERFACE_COMPILE_DEFINITIONS`，同时修复 in-tree 测试与安装包两路消费者。

### H3. 矩阵/变换求逆的失败语义三种并存，且 3D 用"单位变换"伪装失败

- **位置**：`Types/Geometry2d/SCTransform2d.h:62-72`（`std::optional`）vs `Types/Geometry3d/SCTransform3d.h:55-63`（裸值，失败返回 `{}` = 单位变换）vs `Types/Geometry2d/SCMatrix2d.h:54-63` / `Types/Geometry3d/SCMatrix3d.h:59-77`（零矩阵）
- **描述**：同族 API 三种失败信号。`SCTransform2d::Inverse` 返回 `std::optional`，注释明确写着 "SCTransform2d{} is the identity transform and must not be used as a failure value"——而 `SCTransform3d::Inverse` 恰恰就是这样做的：不可逆时静默返回单位阵，调用方无法区分"求逆失败"与"恒等变换"。矩阵版返回零矩阵，也无失败信号。2D 修好了、3D 没修，平行接口断裂。
- **建议**：统一为 `std::optional`（至少 Transform 系列）；矩阵 `Inverse` 若保留零矩阵哨兵，需文档声明"奇异即未定义"并配对 `IsInvertible`。删除 `SCTransform3d.h:58` 处绕弯的守卫逻辑。

### H4. 空间索引类名不副实：每次查询全量重建，`QueryKNearest` eps 形参被忽略

- **位置**：`Source/Geometry2d/SCBoxTree2d.cpp:202-255`、`Source/Geometry2d/SCKDTree2d.cpp:208-249`、`Source/Geometry3d/SCBoxTree3d.cpp:204-257`
- **描述**：三个"索引"类内部只存扁平 `entries_` 向量，`Add/Remove/Update` 只改向量、从不维护树；每次 `Query/QueryContaining/QueryWithinDistance/Nearest` 都从零 `BuildBoxTree/BuildKDTree`（O(n log n)）再遍历，`QueryKNearest` 干脆对全量向量 `nth_element`。单次最近邻查询复杂度反而高于线性扫描。`SCBoxTree2d::QueryKNearest(point, k, double)` 的第三个参数是**未命名形参**，被完全忽略——声明带 `eps = kDefaultEpsilon` 却无实现。另有 `Update` 通过 `const_cast` 改只读查找结果（`SCBoxTree2d.cpp:159`、`SCKDTree2d.cpp:165`）。
- **建议**：要么实现真正持久的树（增量维护），要么改名（如 `SCBoxIndex2d`）并明确"查询时重建"语义；给 `QueryKNearest` 的 eps 实际语义或删除参数。

### H5. BodyBoolean 是披着完整 API 的空壳

- **位置**：`Source/Brep/BodyBoolean.cpp:24-44`（`MakeUnsupportedResult` 的自白）、`BodyBoolean.cpp:1017-1051`、`996-1014`
- **描述**：`IntersectBodies/UnionBodies/DifferenceBodies` 对任何一般体都返回 `UnsupportedOperation`。整文件 ~1000 行围绕"抽取轴对齐盒"的启发式（`FaceMatchesAxisAlignedBox` 对 SCBrepFace 与 PolyhedronFace3d 各写一份，第 269/505 行），只支持"identical / disjoint / 单轴对齐盒 contained/overlap / representative touching"平凡子集，没有真正的 CSG 内核。作为公共 API 存在会让用户误以为"能做布尔"。
- **建议**：要么把 API 改成显式能力声明（如返回能力枚举），要么先落地基于平面裁剪的通用 B-rep 布尔内核；实现前在文档/API 层明确能力边界。

### H6. SCNurbsCurve3d / SCNurbsSurface 名不副实：无权重（实为 B-spline），导数用有限差分

- **位置**：`Include/Geometry3d/SCNurbsCurve3d.h:16-119`、`Include/Geometry3d/SCNurbsSurface.h:16-136`
- **描述**：名称承诺 NURBS，但构造函数只接收 `SCPoint3d` 控制点、**没有任何权重**，即非有理 B-spline；`Evaluate(derivativeOrder>=1)` 的一二阶导用中心有限差分近似（`SCNurbsCurve3d.h:96-117`、`SCNurbsSurface.h:118-134`），而非 Cox-de Boor 解析求导。而 `SCLineCurve3d`/`SCPlaneSurface` 给出解析导数——同一 `ISCCurve3d`/`ISCSurface` 接口下导数精度不一致，直接削弱依赖导数的算法（牛顿求交/投影）。两类的 `Basis()` 递归还各有一份逐行相同的实现且指数级递归未缓存。
- **建议**：补权重（有理）与解析导数（或改名为 `SCBSpline*` 不越界承诺）；抽共享 B-spline 基函数工具。

### H7. 三角化算法重复实现 3 份

- **位置**：`Core/Triangulation.h`（已公开 `Triangulate`）vs `Source/Brep/MeshConversion.cpp:142-516` vs `Source/Brep/MeshRepair.cpp:60-191`
- **描述**：后两处各自手写耳切 + 孔桥接三角化，`TriangulateSimplePolygon` 在两个文件里逐行相同；已有公开 `Triangulate(SCPolygon2d)`（支持带孔）却未复用。
- **建议**：统一复用 `Core/Triangulation.h`，删除私有三角化副本。

### H8. SCPathOps 与 Core/SearchPoly 平行实现同一套多边形重建算法

- **位置**：`Source/Geometry2d/SCPathOps.cpp:928-940` 与 `Source/Core/SearchPoly.cpp:182-194`（打分公式逐行相同）、`BuildMultiPolygonByLines`（SCPathOps.cpp:1209-1250）vs `SearchPolygons`（SearchPoly.h:139-143）
- **描述**：两处各自实现 auto-close/auto-extend/synthetic-edge/分支惩罚的完整重建管线（各 900+ 行），公共逻辑未收敛。`CutPolygon`（SCPathOps.cpp:1173-1207）在无洞路径用手写半边裁剪、有洞路径却委托 Core 布尔，同一函数两套切割算法。
- **建议**：提取共享 2D 环重建内核（SearchPoly 已带诊断/候选排名，建议作收敛目标），CutPolygon 统一走一条路径。

### H9. 通用求交/投影退化为暴力采样 + 坐标下降，且被复制 3 份

- **位置**：`Source/Geometry3d/Intersection3d.cpp:329-363,499-557`、`Source/Geometry3d/Projection3d.cpp:327-480`
- **描述**：线与曲线求交用 33 点采样、线与曲面用 17×9×9 网格 + `RefineLineSurfaceIntersection` 坐标下降；三个 `Refine*` 是同一种 3×3 邻域坐标下降的复制品。采样式算法对窄特征/切点不可靠。`Intersect(line,curve)` 与 `Intersect(line,edge)`（第 271-363 vs 560-653 行）是 ~90 行复制粘贴。
- **建议**：为 ISCCurve3d/ISCSurface 提供基于解析导数的牛顿投影基础（H6 解析导数落地后受益）；line-edge 求交改为 `Intersect(line, *edge.Curve())` 薄包装。

### H10. SCBrep 拓扑访问器全部按值返回，遍历即深拷贝；所有权模型混乱

- **位置**：`Include/Brep/SCBrepBody.h:117-120`（`ShellAt` 按值）、`SCBrepShell::FaceAt`、`SCBrepFace::OuterLoop/HoleAt`；几何却用 `shared_ptr`（`SCBrepEdge::curve3d_`、`SCBrepFace::supportSurface_`）
- **描述**：`body.ShellAt(i).FaceAt(j)` 反复复制整棵子树；`SCBrepBody` 无任何非 const 访问器，编辑只能走 BrepEditing 的"复制-重建-替换"。调用处（如 `Intersection3d.cpp:714-717`）因此产生 O(N²) 级深拷贝。
- **建议**：提供 `const SCBrepShell& ShellAtRef(i)` 等引用访问器，把按值访问器标 deprecated；或让拓扑节点共享 `shared_ptr`。

### H11. 测试体系结构性硬伤（详见 §5）

复核结果（2026-09-01）：Gaps 仍保留 19 个明确禁用项，已完成的能力测试已迁移至 Capabilities 并使用真实断言。`TestCore.cpp` 的三维重复构造已收敛到 `UnitTests/Support/Fixtures3d.h`；`TestSerialize.cpp` 的 7 类 malformed input 已改为参数化测试并补充可读的 GTest `PrintTo` 参数展示。

对 `Test3dSection.cpp` 的 Polyhedron/B-rep 成对测试进行了参数化可行性评估。两组测试虽然场景相似，但 B-rep 用例额外包含 Polyhedron→Brep 转换、不同结果类型及拓扑/转换断言；强行共用参数模型会掩盖转换路径差异，因此保留独立测试。文件内场景构造器具有明确的几何语义，暂不迁移为通用 fixture。

- **位置**：`UnitTests/Gaps/**`、`UnitTests/Capabilities/Core/TestCore.cpp:133`、`UnitTests/CMakeLists.txt`
- **描述**：① Gaps 目录 20 个测试全部 `GTEST_SKIP()` 占位，CTest 全绿但零断言，且把几百行能力边界文档塞进 skip 字符串；② `TestCore.cpp` 单个 `TEST(GeometryTest, CoversCurrentCapabilities)` 占 133-1388 行，失败无法定位到具体行为；③ 全库零 `TEST_F`/`TEST_P`，14 个文件都是单 TEST；④ 立方体/轴对齐盒构造器重复 4~5 份。
- **建议**：占位测试改真实断言或改 `DISABLED_` 前缀（在 CTest 中可见地"被禁用"）；按行为拆分巨型测试并引入 fixture/参数化；构造器收敛到 `UnitTests/Support/Fixtures3d.h`。

## 七、优先处理建议

### P0（发布前必须修）

1. **H2 导出/DLL 契约**：为库加 `INTERFACE GEOMETRY_USE_DLL`，修消费者 dllimport 链。改动小、风险收益比最高。
2. **H1 分层环**：拆分 Core 的"结果/叶子类型"与"算法模块"，消除 Core↔Brep 反向 include。这是所有 include 传染的根源，也是 PCH/重编问题的根源。

### P1（下一个里程碑）

3. **H3 求逆失败语义统一**：`SCTransform3d::Inverse` 改 `std::optional`，矩阵族给出明确契约。
4. **H4 空间索引**：SCBoxTree/SCKDTree 要么真树、要么改名并修 `QueryKNearest` eps。
5. **H11 + §5 测试体系**：Gaps 占位转真实断言或 `DISABLED_`；拆分 `TestCore.cpp` 等巨型测试；收敛 cube 构造器。
6. **H5 BodyBoolean 能力边界**、**H6 NURBS 命名与导数**、**H7 三角化去重**。

### P2（持续收敛）

7. **API 一致性**：M4-M18（2D/3D 平行、容差参数、越界约定、双访问器、成员/自由函数去重）。
8. **重复收敛**：H8 重建算法、H9 采样求交、M27-M33。
9. **文档校准**：D1-D8（README、命名计划乱码、CI 声明、编码规范）。
10. **构建收尾**：M34-M42（版本单一来源、安装过滤单轨化、bat 清理、GTest URL）。
