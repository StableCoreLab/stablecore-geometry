# StableCore Geometry 代码规范

## 1. 命名空间与目录

### 1.1 目录结构

对外头文件目录保持清晰。

```text
Include/
```

这里描述的是源码树中的目录风格；安装后的公开头文件根目录使用 `Include/SCGeometry/`。

### 1.2 命名空间

内部命名空间保持简洁：

```cpp
namespace Geometry
{
}
```

原则：

- 对外源码路径使用 `Include/`
- 对外安装路径使用 `Include/SCGeometry`
- 对内命名空间使用 `Geometry::`

## 2. 类型命名

### 2.1 使用 PascalCase

以下为现有类型名示例，不是前置声明：

```text
SCPoint2d
SCVector2d
ISCSegment2d
SCBox2d
SCSegmentProjection2d
```

`SCPoint2d`、`SCVector2d`、`SCBox2d` 是模板特化别名，使用时包含对应公开头；不能将这些别名写成 `struct` 前置声明。`ISCSegment2d` 是类接口，投影结果 `SCSegmentProjection2d` 定义在 `Core/Geometry2dResults.h`。

### 2.2 维度后缀统一

统一使用：

```text
2d / 3d
```

例如：

```cpp
SCPoint2d // 正确
Point2D   // 不建议
Point2    // 不建议
```

二维段枚举的新代码入口为 `SCSegmentKind2d` 与 `SCArcDirection2d`：

| 旧公开名称 | 新代码名称 |
| --- | --- |
| `SCSegmentKind2` | `SCSegmentKind2d` |
| `SCArcDirection` | `SCArcDirection2d` |

`Geometry2d/SegmentTypes.h` 保留旧枚举定义，新名称是同一类型的别名。公开函数声明、内部实现及主要能力测试使用带维度的新名；现有派生类和调用方仍可使用旧名，枚举值、底层类型及导出符号保持不变。当前 1.x 不通过重定义枚举或新增同义重载实现改名，也不因底层旧名加弃用标记而使新别名触发弃用告警。

## 3. 函数命名

### 3.1 使用 PascalCase

```cpp
Distance
DistanceSquared
Dot
Cross
ProjectPointToSegment
IntersectSegments
```

### 3.2 布尔函数必须表达语义

```cpp
IsZero
IsEqual
IsParallel
IsPointOnSegment
```

### 3.3 禁止无意义前缀

不建议：

```cpp
CalcDistance
DoIntersect
HandleSegment
```

## 4. 变量命名

### 4.1 普通变量使用 lowerCamelCase

```cpp
startPoint
endPoint
distanceSquared
intersectionPoint
```

### 4.2 成员变量命名

公开结果结构和几何值类型的字段使用 `lowerCamelCase`，与现有公开 API 保持一致；实现类的私有存储字段使用 `_` 后缀。不要为了统一前缀批量改动已有公开字段名。

```cpp
struct SCLinePlaneIntersection3d
{
    bool intersects{false};
    double parameter{0.0};
    SCPoint3d point{};
};
```

### 4.3 布尔变量必须可读

```cpp
bool isValid;
bool isParallel;
bool hasIntersection;
```

## 5. 常量规范

### 5.1 使用 `k` 前缀

```cpp
constexpr double kDefaultEpsilon = 1e-9;
constexpr double kPi = 3.14159265358979323846;
```

### 5.2 禁止裸常量

不建议：

```cpp
fabs(a - b) < 1e-9
```

应改为：

```cpp
IsZero(a - b)
```

## 6. 核心数值工具统一

二维标量和二维向量的近似相等判定使用 `Support/Geometry2d/Predicate2.h` 中现有的 `IsZero`、`IsEqual`，容差由调用方传入。`IsLess`、`IsGreater` 尚未提供统一接口，使用它们前须先定义严格比较与容差带的边界语义。

```cpp
#include "Support/Geometry2d/Predicate2.h"

const bool nearZero = Geometry::IsZero(0.0, 1e-9);
const bool nearEqual = Geometry::IsEqual(1.0, 1.0, 1e-9);
```

三维对象和具体算法的容差仍由各自公开接口契约定义；不能把二维谓词直接视为全库统一的数值模型。

## 7. 结果类型规范

### 7.1 复杂算法不要只返回 `bool`

不建议：

```cpp
bool IntersectSegments(...);
```

### 7.2 应返回结构化结果

```cpp
struct SegmentIntersectionResult
{
    bool intersects{false};
    bool parallel{false};
    bool collinear{false};
    SCPoint2d point{};
};
```

调用方通常还关心：

- 是否平行
- 是否共线
- 是否唯一交点
- 交点坐标
- 参数位置

## 8. 文件命名规范

### 8.1 使用 PascalCase

```text
SCPoint2d.h
SCVector2d.h
ISCSegment2d.h
Distance2d.h
Distance2d.cpp
Intersect2d.h
```

### 8.2 一文件一职责

每个文件只承载一个清晰主题，不要把无关工具堆在一起。

### 8.3 三维测试文件与 suite

Geometry3d 目录中的三维专用测试使用 `TestXxx3d.cpp`，差距文件使用 `TestXxx3dGaps.cpp`。普通与参数化 suite 使用 `Xxx3dTest`，能力 suite 使用 `Xxx3dCapabilityTest`，差距 suite 使用 `Xxx3dGapTest`；跨维度共享工具测试按主题归入 Core 并使用通用主题名。用例名描述行为，参数实例保留具名后缀。过滤名称变更需提供迁移对照，见 [T5 测试命名迁移](../审查整改/T5测试命名迁移.md)。

## 9. 接口设计规则

### 9.1 公开 API 保持短名风格

优先：

- `Size()`（容器主计数）
- `Bounds()`
- `PointAt()`
- `Length()`

避免重新扩散：

- `GetCount()`
- `GetBounds()`
- `GetPointAt()`

容器主计数使用 `Size()`；`PointCount()`、`HoleCount()`、`ShellCount()` 等具名计数表达不同集合，不机械替换。已弃用的 `Count()` 仅按当前 1.x 兼容规则保留转发，新代码使用主入口；具体迁移见 [M4M14接口现状与迁移](../审查整改/M4M14接口现状与迁移.md)。

### 9.2 成员函数与自由函数边界要清楚

成员函数适合：

- 直接读取对象自身状态
- 不依赖外部上下文的天然属性

自由函数适合：

- 涉及多个对象
- 需要容差或上下文
- 算法复杂度较高

## 10. 测试与文档一致性

新增或修改 API 时，应同步更新：

- 对应测试
- 相关设计文档
- [结构收敛交接](../结构收敛交接.md)中的当前状态说明

代码、测试、文档三者应保持同一口径。

公开 C++ 接口的导出宏、外部数据和兼容规则见 [公开接口与导出规范](公开接口与导出规范.md)。
