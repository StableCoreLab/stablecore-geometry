# 公开接口与导出规范

本规范描述当前 1.x 的导出约定。宏定义以 `Include/Export/GeometryExport.h` 为准，target 定义以根 CMake 为准；不能按 Types／Core 目录名称机械添加或删除导出宏。

## 声明规则

- 具有库内非内联实现的公开函数、类及既有公开结果类型使用 `GEOMETRY_API`，声明头直接包含宏定义头。结果类型中有内联成员不构成删除既有导出标记的理由。
- 头内定义的通用模板和纯头内值类型按实际实例化方式处理，不统一增加 DLL 导出标记。Types 中同时存在模板类型和具名导出类型，例如 `SCBox3<T>` 与 `SCGeometryTolerance3d`，两者不是同一规则的遗漏。
- 需要单一库内定义的公开变量在头中用 `extern GEOMETRY_DATA_API` 声明，在实现文件中定义一次。当前包括标量及 `std::array<double, 4>` 的临界角数组。
- 纯实现助手不新增公开导出；已位于公开头的 Detail 声明及既有符号迁移须单独审查兼容性，不能仅据命名空间删除。

## 当前宏行为

| 使用场景 | GEOMETRY_API | GEOMETRY_DATA_API |
|---|---|---|
| Windows／Cygwin 构建动态库，定义 GEOMETRY_BUILD_DLL | dllexport | dllexport |
| Windows／Cygwin 消费动态库，定义 GEOMETRY_USE_DLL | 空 | dllimport |
| 静态使用，未定义上述宏 | 空 | 空 |
| 其他平台的当前实现 | 空 | 空 |

动态库消费者的代码宏保持为空是现有头内成员兼容策略；数据仍使用 dllimport。不要只将代码宏改为 dllimport 而不核对所有内联类成员与消费者。根 CMake 在共享构建中为库私有定义 GEOMETRY_BUILD_DLL，并向消费者传递 GEOMETRY_USE_DLL；静态配置不应发布该导入定义。

## 兼容与验证

`kPi`、`kTwoPi`、`kArcBoundsCriticalAngles` 和已弃用容差别名的外部符号在当前 1.x 保留。不能为了形式统一将已有 extern 数据改成头内 constexpr，也不能仅因不再内部使用而删除导出；两者都会改变符号或对象身份。新增默认阈值应优先表达量纲和用途，避免继续扩展无实际调用的默认别名。

公开 C++ 接口的模板、STL 容器和类布局属于所使用编译配置的 ABI，不将当前导出策略解释为跨编译器的通用二进制协议。公开头独立编译检查包含完整性；安装后消费者检查 target 定义、代码链接和数据访问。`SCGeometry.PackageConsumer` 实际读取两个圆周常量及四元素临界角数组，并核对共享／静态导入定义。需要改动对象布局、导出符号或 STL 载荷时，应增加相应安装后消费验证；静态库也须使用独立配置验收。
