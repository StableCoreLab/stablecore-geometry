# StableCore Geometry 设计说明

## 1. 定位

StableCore Geometry（工程标识 `SCGeometry`）是面向工程计算的 C++20 几何库。设计目标是提供稳定、可测试、可发布的几何能力，并通过清晰的模块边界控制 API、数值行为和持久化兼容性。

## 2. 模块分层

```text
Types / Support
    ↓
Geometry2d / Geometry3d
    ↓
Brep
    ↓
Core
    ↓
Serialize / Export
```

- `Types`：几何值类型和基础数据结构，尽量保持 header-only。
- `Support`：容差、谓词、归一化等基础辅助能力。
- `Geometry2d`：二维图元、路径和二维专用服务。
- `Geometry3d`：三维值类型、曲线、曲面和网格能力。
- `Brep`：拓扑、Polyhedron、BRep、网格转换、修复和三维实体服务。
- `Core`：跨模块的相交、投影、关系、度量、布尔、偏移、验证、搜索和截面门面。
- `Serialize`：持久化格式和编解码，不依赖对象内存布局。
- `Export`：跨 DLL 的符号导出约定。

公共头文件位于 `Include/`，实现位于 `Source/`，内部实现细节不得作为公共 API 依赖。

## 3. 公共 API 原则

### 3.1 运行时对象与持久化格式分离

运行时对象表达几何语义；持久化记录表达稳定的类型标识、定义版本和字节载荷。持久化格式不得使用 C++ RTTI 名称、对象地址、对象内存布局或显示采样点。

### 3.2 类型和版本策略

- `typeId` 标识稳定的几何语义族，例如 `SC.LineSegment2d` 和 `SC.ArcSegment2d`。
- `definitionVersion` 只表示同一 `typeId` 的二进制定义格式版本。
- 新版本应解码并迁移到同一运行时几何语义。
- 几何语义不兼容时必须创建新的 `typeId`，不能只提高版本号。

### 3.3 结果和错误

可能失败的操作优先返回结构化结果。成功时结果对象有效，失败时通过专用枚举表达原因，不以异常作为普通输入错误通道。

### 3.4 容差

几何算法必须显式使用默认容差或调用者提供的容差。长度、角度、参数域和包围盒边界不能混用没有物理意义的单一比较规则。

## 4. 二维段内核

`Source/Detail/SegmentKernel2d` 是同一 `SCGeometry` 二进制模块内的内部能力边界，用于统一 Line、Arc 及未来内置段类型的运行时行为。它不作为公共头文件导出。

内部段描述符负责：

- 精确反向；
- 批量 `SplitAtParameters`；
- 确定性采样；
- 已知定义版本的编码和解码；
- 与其他内置段类型的精确相交。

批量分割结果必须保留源段参数区间，并按原始参数严格递增。未注册类型或缺少能力时返回正式失败，不进行隐式折线降级。

## 5. 段编解码协议

当前支持：

- `SC.LineSegment2d`，定义版本 `1`，四个 binary64 值；
- `SC.ArcSegment2d`，定义版本 `1`，五个 binary64 值。

完整段记录按规范小端编码：

```text
uint32 typeIdLength
byte[] typeId
uint32 definitionVersion
uint64 payloadLength
byte[] definitionPayload
```

`typeIdLength` 最大为 256，`payloadLength` 最大为 4096。解码必须精确消费全部记录，不接受截断或尾随字节；必须检查有限值和最终 `IsValid()`。平台不满足 IEEE-754 binary64 约束时返回 `UnsupportedPlatform`。

对外调用者只提交完整记录：

```cpp
[[nodiscard]] GEOMETRY_API SCSegmentDecodeResult DeserializeSegment(
    std::span<const std::byte> serializedRecord);
```

`typeId`、`definitionVersion` 和 `definitionPayload` 的拆分及路由属于内部解码流程。

## 6. 二维路径和多边形

曲线 arrangement、精确分割、规范化和三角化必须使用统一的段内核，不得通过重复采样逻辑产生不一致的参数或拓扑结果。结果应保留源段索引、源参数和确定性顺序，便于重放、诊断和持久化。

## 7. 三维实体分层

`PolyhedronBody` 与 `BrepBody` 表达不同层次的实体语义，不应过早合并：

- `PolyhedronBody` 面向平面主导的工程实体工作流；
- `BrepBody` 面向精确边界表示、高阶曲线曲面和复杂拓扑；
- BRep 必须保留 `Vertex / Edge / Coedge / Loop / Face / Shell / Body` 层次；
- `Coedge` 用于表达同一边在不同 loop/face 中的方向使用关系。

## 8. 发布和兼容性

- 公共 API 通过 `GEOMETRY_API` 导出；
- 内部实现不进入安装后的公共头文件；
- 公开结构的所有权、异常和 ABI 约定必须保持稳定；
- 新能力应先明确语义、错误契约和持久化影响，再实现和验证。

## 9. 容差与确定性

容差是算法契约的一部分，而不是实现内部的随意常量。二维算法通常接受 `double` 容差，三维算法使用包含距离、角度、参数和包围盒余量的专用容差结构。调用者需要保证容差为有限正数；算法不能把负数、NaN 或无穷大当作正常容差。

需要稳定输出的算法还必须固定：

- 输入环、段和交点的排序规则；
- 事件合并的坐标阈值和参数阈值；
- 曲线采样的分段规则；
- 网格顶点、索引和三角形的编号规则。

同一输入、同一算法版本和同一容差应产生相同的拓扑顺序和结果编号。算法规则发生不兼容变化时，应提高结果中的 `algorithmVersion` 或引入新的能力契约。

## 10. 曲线 Arrangement 与多边形流程

涉及曲线边界的规范化流程必须经过以下阶段：

1. 验证所有环闭合、段有效且坐标有限；
2. 对非相邻段、外环和孔执行精确曲线求交；
3. 按源段参数排序交点并分割为原子边；
4. 去除重复原子边，保留方向和源段参数；
5. 构造确定性的半边关系；
6. 遍历面环并依据填充规则分类；
7. 输出规范化 polygon 或三角网格。

不能用固定采样点代替上述拓扑判断。Arc 必须保留为曲线段，不能在精确关系运算中隐式降级为折线。

失败结果必须携带第一个可定位的 `loopIndex` 和 `segmentIndex`（若该 API 提供定位字段），不得把边界接触、重叠、孔嵌套错误伪装成 `Disjoint`。

## 11. 平面与多边形 API 设计契约

平面构造、平面标高求值、多边形规范化、包含关系和三角化等能力都遵守统一结果模式：

```cpp
struct Result
{
    bool success{false};
    Value value{};
    Failure failure{Failure::None};
};
```

成功时 `success == true` 且 `failure == None`；失败时 `success == false` 且必须提供非 `None` 的原因。失败结果中的几何值保持默认值或明确标记为不可用，不能返回部分构造结果并要求调用者猜测其有效性。

多边形规范化应区分：

- 自交、边界重叠和边界接触；
- 孔在外环外、孔相交和孔嵌套；
- 无法确定的拓扑关系；
- 三角化索引溢出、退化和面积不一致。

### 11.1 平面

`Core/PlaneOps.h` 提供三类平面服务：

```cpp
CreatePlaneThroughThreePoints(first, second, third, tolerance);
CreatePlaneFromPointAndXYGradient(referencePoint, xyDirection, risePerRun, tolerance);
EvaluatePlaneElevationAtXY(plane, xyPoint, tolerance);
```

三点构造需要依次拒绝非有限输入、重合点和共线点。梯度构造要求 XY 方向非退化；高程求值必须拒绝垂直或近垂直平面，不能返回钳制值、无穷值或未经说明的近似值。

### 11.2 多边形

`Core/PolygonTopology.h` 提供：

```cpp
NormalizePolygon(polygon, validationTolerance);
TessellateAndTriangulatePolygon(polygon, validationTolerance, deterministicTolerance);
ClassifyContainment(container, candidate, validationTolerance);
AppendHole(polygon, hole, validationTolerance);
```

`NormalizePolygon` 输出方向规范的外环和洞环；`TessellateAndTriangulatePolygon` 输出带来源段参数和稳定顶点编号的边界顶点及三角形；`ClassifyContainment` 的失败状态为 `Unknown`，不得以 `Disjoint` 代替失败；`AppendHole` 只有候选环严格位于外环填充区时才成功。

## 12. 测试和验证原则

每个公共能力至少需要覆盖：

- 正常输入和最小有效输入；
- 空、截断、退化和非有限输入；
- 容差边界和尺度变化；
- 未知类型、未知版本和不支持平台（如适用）；
- 结果的几何有效性、拓扑关系和确定性。

公共头文件应能独立包含，安装后的消费者应能通过导出的 CMake target 使用库。设计文档描述的是长期契约；测试名称和实现细节不应替代契约本身。
