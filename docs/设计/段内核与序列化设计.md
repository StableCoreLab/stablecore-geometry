# 段内核与序列化设计

## 1. 内部段内核

`SegmentKernel2d` 是 `SCGeometry` 同一二进制模块内的内部能力边界。它不导出注册函数、回调、句柄或动态插件机制；新增内置段类型必须随 SCGeometry 源码、测试和二进制一起发布。

内核以内部描述符识别 Line、Arc 和未来内置类型，提供精确反向、批量分割、确定性采样、已知定义版本编解码和内置段间精确相交。未注册类型或缺少能力时返回正式失败，不做折线降级。

批量分割按源参数严格递增，返回每个原子段及其源参数区间：

```cpp
struct SCSegmentFragment2d
{
    std::unique_ptr<ISCSegment2d> segment{};
    double sourceStartParameter{0.0};
    double sourceEndParameter{1.0};
};
```

曲线 arrangement 只可依赖批量分割，不能通过多次单参数分割推断后续参数。

## 2. 身份和版本

运行时几何语义与持久化格式严格分离：

- `typeId` 标识稳定语义族，例如 `SC.LineSegment2d`、`SC.ArcSegment2d`；
- `definitionVersion` 只描述同一 `typeId` 的二进制定义格式；
- 新版本必须迁移为同一运行时语义；
- 语义不兼容时创建新的 `typeId`，不能仅提高 `definitionVersion`。

持久化格式不得使用 C++ RTTI 名称、对象地址、对象内存布局或显示采样点。

## 3. 完整段记录格式

公开解码接口只接收完整记录：

```cpp
[[nodiscard]] GEOMETRY_API SCSegmentDecodeResult DeserializeSegment(
    std::span<const std::byte> serializedRecord);
```

记录使用规范小端：

```text
uint32 typeIdLength
byte[] typeId
uint32 definitionVersion
uint64 payloadLength
byte[] definitionPayload
```

`typeIdLength` 最大为 256，`payloadLength` 最大为 4096。解码必须精确消费全部字节，不接受空类型、截断记录或尾随字节。

当前定义：

| 类型标识 | 定义版本 | 载荷 |
|---|---:|---|
| `SC.LineSegment2d` | 1 | 起点和终点的四个 IEEE-754 binary64 值 |
| `SC.ArcSegment2d` | 1 | 圆心、半径、起始角和扫角的五个 IEEE-754 binary64 值 |

## 4. 解码和错误契约

解码过程先解析记录元数据，再由内部函数按类型和版本解释载荷。调用者不需要也不应自行拆分 `typeId`、版本和 payload。

解码必须检查：平台支持 binary64、长度精确匹配、全部浮点值有限、构造后的段 `IsValid()`。错误含义如下：

- `UnknownTypeId`：当前库不支持该语义族；
- `UnknownDefinitionVersion`：当前库不支持该格式版本；
- `MalformedPayload`：记录结构、长度或字节消费不正确；
- `NonFiniteDefinition`：载荷包含 NaN 或无穷大；
- `InvalidDecodedSegment`：数值可读但不构成有效几何；
- `UnsupportedPlatform`：当前平台不满足 binary64 约束。

未知类型或版本的原始记录应由调用方保留，以便使用支持该定义的版本重新处理。
